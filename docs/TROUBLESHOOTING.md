# 故障排查与已知限制

[首页](../README.md) · [使用手册](USAGE.md)

原服务已撤除。本文用于源码研究/重建测试，不代表维护中的线上服务或稳定性保证。

## 1. 分段定位

```text
出口端HTTPS报到 → 节点获准 → SSH反向通道
使用方 → SS公网TCP/UDP → 鉴权/限速/目标闸门 → 朋友 → 目标站
```

同一时刻记录节点状态、最后心跳、通道实际响应、外部SS结果、真实目标完整错误。分享时脱敏，不发密码、私钥、完整SS链接、identity或数据库。

## 2. 常见现象

| 现象 | 优先检查 |
|---|---|
| 一直待启用 | 正常审核；管理员认领并启用，不是朋友改密码 |
| 设备不出现 | Bootstrap地址/域名/注册令牌、443/证书、HTTPS路由、节点数/注册限流 |
| SSH banner exchange超时 | 22可达性、物理适配器、网关/TUN/热点；发生在身份校验前，不直接认定私钥错 |
| SSH主机校验失败 | 可信通道核对公钥/known_hosts，不关闭严格校验 |
| Endpoint not allowed | NetBridge固定端点是否与Bootstrap同步 |
| GOST/桥校验失败 | 二进制版本/重编译哈希与Common.Verify不符；核验后更新，不跳过校验 |
| 心跳在线但不通 | 心跳与数据链不同，测反向端口实际响应、旧链卡死、容量、鉴权代次 |
| TCP通UDP不通 | UDP规则、客户端兼容、映射/TTL、出口DNS、UDP-over-TCP通道 |
| 新节点不能导出 | 启用、密码、在线、direct_open_slots、实际云/主机端口 |
| 密码框不能改 | 参数窗口只读，走“设置/更换节点密码” |
| 保存后503 | 可能已保存但入口未同步，先查最新版本，不重复换密/恢复旧库 |
| API 401/403 | 会话、Cookie/CSRF/Origin/Host/私有代理头，不以关闭认证修复 |
| 速度慢 | 总256KiB/s共享、节点限制、朋友上行、线路、SSH队头阻塞 |
| 容量满 | 活跃/未完成会话占满32/64，有界拒绝是保护，不无限加资源 |

## 3. 检测正常但IP没变

在实际被代理的程序/系统里查，区分VM和宿主；确认类型SS、密码/端口/所选节点。朋友与使用者若本就同出口，IP可能一样，需与朋友当次公网IPv4对照而非旧截图。

旧V3进程启动器曾因浏览器后台/网络子进程复用没有接管；“已启动”不等于真实代理。V3.0.2对支持Chromium改独立资料目录+原生HTTP代理，并限制非代理WebRTC UDP/QUIC，不共享原登录/扩展、不保证任意EXE。

IPv6、DNS、WebRTC、QUIC、TUN、客户端规则分别核对；一次IPv4查询不等于全协议防泄漏。

## 4. ERR_CONNECTION_CLOSED / 登录器TLS文案

“启用TLS 1.0/1.1/1.2”可能只是通用错误页，不能仅凭它认定TLS设置错，也不要为此关证书验证或启用旧算法。

相同目标做三组对照：使用方直连、朋友直接访问、使用方经SS；记录域名/DNS候选、握手中断阶段、时间、活跃会话和通道响应。可能涉及链假在线、容量、DNS排队、空闲/半关闭、目标策略、两地DNS线路不同、客户端兼容或代理循环。

朋友直接访问正常、查IP是朋友出口，仍不能证明全部转发正常；也不能直接断言目标站封锁，必须逐段取证。

## 5. 历史修复与未解决

- V4.3：DNS有界排队/合并/取消隔离、UDP空闲处理，不代表所有站永远可用。
- V4.4：压力下回收已完整响应的DNS-only UDP；SQLite连接显式关闭、末次容量竞争检查。保留活跃/未完成流量。

- 部分查询站TLS EOF，在某些直接朋友通道对照中也失败；不能全归同一bug，不抹去失败记录。

## 6. 任意EXE必走代理？

原生代理、进程拦截、系统代理、TUN/TAP作用层不同。系统服务代发、内核驱动、已有子进程、UDP/IPv6与自定义协议都影响实际路径。最终V4解决标准SS出口，不提供不可绕过的Windows按EXE策略。强制隔离/失败阻断应另行设计并针对真实应用验收。
