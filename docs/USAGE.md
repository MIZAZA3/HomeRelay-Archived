# 详细使用手册

[首页](../README.md) · [功能](FEATURES.md) · [构建部署](BUILD_AND_DEPLOY.md) · [排查](TROUBLESHOOTING.md)

## 0. 使用前提

原部署已完整撤除，仓库不提供可用服务器、节点密码或现成运行包。本手册描述的是**管理员独立完成重建和验收后**的使用流程，不是连接文档示例。`203.0.113.20`、`203.0.113.30`、`relay.example.invalid` 都不是可用节点。

管理员负责Ubuntu、公网IP/域名、HTTPS、受限SSH、节点端口、管理口令和出口端构建。朋友收到配置到该部署的出口端；使用者只收到获准使用节点的SS参数。

朋友通常不需要路由器入站映射，需能出站到服务器443/TCP和约定SSH（源码默认22/TCP）。使用者需能访问节点的SS TCP/UDP端口。

## 1. 朋友：启动出口端

1. 完整解压管理员交付的干净出口端运行包，别只复制主EXE。
2. 确认Windows有OpenSSH客户端，运行目录有管理员核验的GOST和NetBridge。
3. 正常打开 `HomeRelayAgent.exe`，点击 **启动转发**。不需要为此更改系统代理/FlClash或安装虚拟网卡。
4. 首次会生成独立设备身份并注册；“等待管理员启用”是正常待审核状态。
5. 告诉管理员节点ID/备注即可，**不要发identity中的秘密文件**。
6. 管理员启用后，等待“通道已建立/就绪”，保持窗口、网络和电脑运行。
7. 点击停止或关闭窗口结束共享；睡眠、关机、断网都会中断出口。

| 状态 | 含义 |
|---|---|
| 已停止 | 本次未运行转发 |
| 等待管理员启用 | 报到成功但未获准承接流量 |
| 已启用，正在建立通道 | 审核已过，SSH/GOST数据链尚未就绪 |
| 已启用，通道就绪 | 进程认为通道建立，仍需端到端检测 |
| 在线闲置 | 继续报到，可保留通道，不承接使用方流量 |
| 已被管理员停用 | 管理员拒绝/停用，停止承接与通道 |
| 正在连接/自动重连 | 网络或服务暂不可用 |
| 启动未完成 | 查看末尾错误；常见缺依赖、校验不符、身份创建失败 |

设备身份受Windows用户保护。不要把运行过的 `identity/`、`runtime/` 当通用包复制给每个朋友；否则可能复制同一设备身份。

## 2. 管理员：发现与启用

1. 打开**自己部署**的HTTPS管理页，原设计路径 `/relay-admin/`。
2. 用独立管理口令登录，不是网站会员密码/SSH密码/节点使用密码。
3. 朋友启动后节点自动出现，无需预建名单；核对ID、来源和朋友本人，再设置备注。
4. 核对节点 `slot`，其公网端口为 `direct_base_port + slot`。
5. 仅为该端口开通主机和云防火墙TCP/UDP，并在 `direct_open_slots` 中明确允许该槽位；**面板不会自动修改云控制台**。
6. 点击 **启用**，等待心跳在线、SSH通道与SS入口就绪。
7. 设置节点独立使用密码，运行 **TCP/UDP检测**，另从外部标准SS客户端验证完整公网入口。
8. 验证后再把参数给使用者。

原部署曾仅开通slot0的24443/TCP+UDP，现在已删除。自动出现更多节点不表示其它槽位已开公网端口。

### 节点操作的区别

| 操作 | 使用方流量 | 朋友侧 | 恢复 |
|---|---|---|---|
| 启用 | 在线/认证/端口满足条件时允许 | 建立或保持通道 | 检测后使用 |
| 闲置 | 停止该节点已有和新转发 | 继续报到，可保持SSH | 再启用；未换密时原配置可再次生效 |
| 拒绝/停用 | 停止该节点流量 | 轮询得知后停止通道，仍可报到 | 管理员可重新启用；不是删除设备 |
| 更换密码 | 旧密码/旧连接失效 | 不需要修改使用密码 | 使用方更新配置 |
| 撤销使用权限 | 撤销使用凭据并切断旧连接 | 不等于删除设备身份 | 重新设置密码并核对状态 |
| 朋友停止/离线 | 出口不可用，心跳超时拒绝转发 | 进程/网络已断 | 朋友重启再验证 |

**临时停用不是永久撤销密码。** 不希望旧配置再次使用，应明确换密/撤销，而非只点闲置。

## 3. 设置和更换密码

1. 节点卡片点击 **设置 / 更换节点密码**。
2. 两次输入新的8–128字符密码；不含控制字符，不能重复当前或近期历史值。
3. 点击 **保存自定义密码**，或用 **随机生成并更换**。
4. 等服务器成功确认，再打开 **查看 / 导出 SSTap · FlClash** 获取生效值。
5. 通知使用方更新，旧会话会中断。

“标准代理参数”里的密码框是**只读展示**，不是编辑入口。仅打开窗口不改变密码；若返回“已保存、入口正在同步”，先复核最新版本，不把旧参数当成成功结果。

SS链接和YAML内含密码。关闭对话框/退出会尽力清除页面字段，不会清掉使用者已下载文件或系统剪贴板。

## 4. 最高上传/下载速度

1. 点击 **设置最高网速**，分别填上传/下载，单位KiB/s。
2. `1–256`为节点上限；`0`继承服务器总上限，不是不限速。
3. 点击 **保存限速**，再打开复核。

“两项恢复继承”只把表单改为0/0，仍须保存。上传/下载以**使用方**为视角，节点全部TCP/UDP连接合计计费，不是每人/每连接各一份。

例如A上传64、下载128，代表A所有连接合计最多约64/128KiB/s；全部节点每方向仍共享256KiB/s。256KiB/s约2.1Mbps，上限不是保底，实际受朋友上行、线路和共享负载影响。

## 5. SSTap 1.0.9.7

本项目按该历史版本设计兼容，不称其“最好/最新版本”，仓库不分发SSTap及驱动。

| 字段 | 填写 |
|---|---|
| 类型 | **Shadowsocks**，不是SOCKS5 |
| 服务器/IP | 管理员导出的真实中转地址，不是朋友内网IP |
| 端口 | 对应节点独立SS公网端口 |
| 加密方式 | `aes-256-gcm` |
| 密码 | 当前导出的节点使用密码 |
| 用户名 | 不填 |
| 协议/混淆（如有） | `origin` / `plain`，无额外插件 |

也可导入面板生成的SSTap链接；客户端SS链接编码支持不同，失败时手填字段。

1. 保存节点并测TCP/UDP，再测一个简单网页，然后测真实业务目标。
2. 在**实际被接管的系统/虚拟机**内查询出口，预期是朋友宽带公网IP，而非中转IP。
3. 只在VM运行SSTap不会自动改变宿主浏览器IP；宿主FlClash状态也不能直接说明VM路径。
4. 避免多个全局/TUN/TAP同时争夺同一路径，核对到代理服务器本身的连接没有绕回代理。
5. 项目没有为SSTap新增“按EXE强制代理”内核能力，全局接管范围由客户端决定。

## 6. FlClash

1. 面板打开节点参数，点 **下载FlClash配置**。
2. 导入为独立配置，保留原配置/订阅，不覆盖唯一副本。
3. 选择该配置和 `HomeRelay` 组，再按需要**手动**启用系统代理或TUN。
4. 导出文件不自动开启TUN、不自动修改已有FlClash配置；确认本机mixed-port不冲突。

字段示例，仅示意，不提供真实服务：

```yaml
mixed-port: 7890
allow-lan: false
mode: rule
log-level: warning
ipv6: false
tun:
  enable: false
proxies:
  - name: HomeRelay-example
    type: ss
    server: relay.example.invalid
    port: 24443
    cipher: aes-256-gcm
    password: "REPLACE_WITH_YOUR_NODE_PASSWORD"
    udp: true
proxy-groups:
  - name: HomeRelay
    type: select
    proxies:
      - HomeRelay-example
rules:
  - MATCH,HomeRelay
```

导出不设DIRECT回退，不等于对所有操作系统进程实现强制防泄漏。系统代理只影响遵守它的应用；DNS、IPv6、WebRTC、TUN与已有连接分别验收。

字段依据：[mihomo SS](https://wiki.metacubex.one/config/proxies/ss/)；客户端：[FlClash](https://github.com/chen08209/FlClash)。

## 7. HTTP/SOCKS5与旧连接器

最终公网V4只提供SS，不能把SS端口填进裸SOCKS5/HTTP框。只支持HTTP/SOCKS5的软件可另由兼容客户端转换成本机入口，不是一个公网端口混用所有协议。

历史V2/V3连接器有本机SOCKS5基础端口、HTTP+1、SS+2、指定程序等；其consumer连接卡/回调路线在最终V4退役，运行旧连接器不能自动兼容V4。

V3.0.2对支持的Chromium使用独立临时资料目录和原生HTTP代理，不共享原登录/扩展。其它EXE进程代理仍有兼容性限制；全局模式默认关，未完成本项目TUN实网验收。见[历史说明](../windows/connector-v3.0.2/README.md)。

## 8. 正确验收

按顺序检查：注册心跳→SSH实际数据响应→面板探测→外部SS公网TCP/UDP→实际浏览器/游戏/EXE的出口IP→并发/空闲/长会话→错误密码、换密、闲置、停用、离线、私网目标均被拒绝。

检测成功只对应当次探测，不表示所有目标和长期体验达标。归档没有通过用户VM/游戏的最终长期验收，问题按[排查指南](TROUBLESHOOTING.md)留证。
