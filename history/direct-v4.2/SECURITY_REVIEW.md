# HomeRelay Direct V4.2 安全与限速检查

2026-11-01，北京时间。范围是当前 HomeRelay 控制 / 网页网关 / 标准 SS 入口 / 朋友通道组合，不是全站或操作系统的全面渗透测试。

## 发现并处理

### 1. 解析前内网黑名单不足（重要，已修复并发布）

原服务按目标字符串检查 CIDR。如果客户填写域名，而它随后解析到私有 IP，黑名单不等同于解析结果检查。已在全新网络 namespace 用自建 `127.0.0.1` marker 复现：直接私有 IP 被拒绝，映射至该地址的域名可到达 marker。没有探测真实朋友的局域网或设备；这是本应用组合的边界缺口，不冒称某个上游 CVE。

经用户确认，在认证数据闸门对 TCP CONNECT 和 UDP-over-TCP 每个目标校验：
- 只允许公网地址；拒绝私有、共享、回环、元数据、链路本地、组播、保留、特定地址转换前缀，以及本服务器 IP。
- 域名所有解析答案均须允许；混合公网 / 内网答案也拒绝。
- 转发地址改写为已验证的数字 IP，朋友不再对该域名二次解析；30 秒短缓存仍保存固定地址，过期重新校验。
- DNS 并发 4、队列不无界增长、等待 4 秒、缓存 256 条；失败关闭，不向服务器直接出网回落。
- 特殊用途 / 地址转换范围另有保守的显式列表，保持原 192.0.0/24 整段限制并拒绝已弃用 6to4 / IPv6 特殊协议和文档范围，避免系统 Python 的地址分类版本差异；在 Ubuntu 实际解释器验证，不只在 Windows 单元测试。

实际标准 SS TCP 测试与 GOST UDP-over-TCP 帧测试覆盖合法域名、私有 / 混合答案、缓存固定和过期后重绑定。合成单元补充 IPv4-mapped IPv6、NAT64 / 6to4 / Teredo 前缀、组播、zone ID 等拒绝。

影响：域名可能改由中转解析，CDN 就近结果可能变化；不再支持访问朋友内网。只允许公网 IP 不是内容过滤，也不能阻止公网网站自身提供二次代理。

### 2. 并发凭据修改约束不完整（低风险，加固完成）

旧随机换密 / 撤销仍兼容缺少 `expected_revision` 的旧管理请求；虽始终要求登录与 CSRF，但并发旧页面可能覆盖更新。现在所有凭据写操作均须当前整数版本；缺失 / 旧版本拒绝。不是匿名认证绕过，也不防止已经持有有效管理员会话的人主动换密。

### 3. 已保存但同步失败的信息被网关掩盖（运维缺陷，已修复）

网关原本把所有后端 5xx 改成泛化错误，用户可能误以为换密未发生。现在仅白名单转发固定的“已保存、旧凭据失效 / 等待应用”等信息，不透传任意异常或秘密。

### 4. UDP 会话持续性与额度放大（可靠性 / 防绕限速）

显式启用 GOST UDP listener keepalive。旧默认逐包会话可能快速用尽单节点 16 个关联，不能据此误判为加密失败。保留 64 全局 / 16 单节点并发、CPU / 内存 / FD 限额。

新增限速在认证节点闸门聚合所有 TCP / UDP：上传、下载独立，每个节点与全局两个桶同时扣费，避免先预订全局额度、延迟后集中突发的错误。不同连接 / 协议不能各自获得一整份额度。降低速度清除旧速率积存 token，热更新不改密码和 GOST 进程。

## 验证结果

- **100 / 100 项隔离集成通过**；生产库 / 真实节点密码不用于变更测试。
- 32 KiB 上传、8 KiB/s 上限约 **3.961 秒**；32 KiB 下载、16 KiB/s 约 **1.944 秒**。
- 两条 16 KiB 上传共用 8 KiB/s 约 **3.979 秒**；TCP + UDP 合计 32 KiB 共用该额度约 **3.999 秒**。
- 两节点合计 256 KiB 继承共享 256 KiB/s 约 **1.106 秒**。短时有最多 4 KiB 的桶突发；计量不是全链路物理网卡字节，封装与系统开销另计。
- 实际已有流上调 / 下调限速通过，另一节点无串用额度，凭据 / GOST PID 不变；0 继承而非无限速。
- 登录 / CSRF / Host / Origin、JSON 与大小 / 类型、未知节点、标签注入 / URI 转义、Agent 不能自启用、旧凭据 / 坏密文拒绝均通过。
- 正式网站表单已保存并重新读取 `0 / 0`（保持原上限，限速 revision=2）；没有代用户保存真实密码。
- Windows 独立标准 SS 公网 TCP HTTPS + UDP DNS 均成功，出口 **203.0.113.30**；错误密码及服务器管理 / 回环 / 两种元数据地址负例通过。
- 补强后同一代码也记录过一次 TCP `SSLEOFError`、另一次 UDP DNS 超时；最终再测两者均成功、服务器朋友通道检测也均通过。原始失败与重测文件都保留，未给偶发失败认定未证实的根因，不把短次验收当长期稳定性证明。
- 11 个预期 TCP 端口回归通过；内部服务、1Panel 未新增公网可达入口；云 / UFW 没有本轮变更。
- 服务 UID 996 公网新建连接拒绝；IPv4 / IPv6 UID 链保留。私有 Unix 管理 API 0600，状态目录 0700，源码 root-owned；controller 非特权、NoNewPrivileges、独立资源限额仍在。
- 三个网站业务容器 healthy，容器 ID / 启动时间和 SSH PID 未变；首页 / 公共路由采用最新生产前像并保持不变。FlClash 原三个进程 PID 保留。临时测试客户端与 31980 / 31990 监听已关闭。
- 并行网站任务在两次 HomeRelay 发布之间更新过首页 / 路由；守卫先中止，随后重取最新前像，没有用旧包恢复 / 覆盖别的聊天成果。详见 OPERATIONS.md 与补丁报告。

## 依赖核对与边界

- 沿用 GOST 3.3.2；公开公告未发现不代表没有漏洞。本轮没有替换第三方二进制。
- 实际 Ubuntu 包为 `python3-cryptography 41.0.7-4ubuntu0.4`、`python3.12 3.12.3-1ubuntu0.17`、`openssl 3.0.13-0ubuntu3.16`。不能凭基础版本号忽略 Ubuntu 回补，也不能据此保证所有包最新。
- 审阅 cryptography 公告中涉及 PKCS#7 / PKCS12、非连续内存视图及 wheel 捆绑 OpenSSL 等条件；本功能只用 Fernet 字节输入，没发现这些公告在当前调用路径的触发点。未进行系统 apt 升级 / pip 替换。
- 存储认证加密不提高用户弱密码本身的强度。管理 / 节点口令仍需分别保管，下载的 YAML 和剪贴板仍含秘密。
- **残余架构风险**：面板与主站同源。若主站其他模块有同源 XSS，用户有效的管理会话可能受影响；Cookie Path 不是来源隔离边界。本轮不擅自新增管理子域名 / 证书 / 云规则。进一步隔离应另迁独立管理来源或恢复私有 SSH 访问。
- 没有执行 DDoS 压力、全部依赖 / OS 审计、真实朋友内网探测、游戏 / SSTap TAP / FlClash TUN 验收。没有“绝无漏洞”结论。
