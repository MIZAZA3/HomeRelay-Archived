# 3.0.2 验收记录（2026-11-01）

## 已确认的问题
用户在普通 Edge 的 IP77 网页看到本机出口 `203.0.113.30`。当时独立 Edge 主进程和 Network Service 没有载入代理接管组件，Network Service 同时有直接外网 TCP/IPv6 连接。因此不能把“独立浏览器已启动”当作代理成功。3.0.1 的无头验证没有覆盖这一实际普通窗口路径。

## 本次修复与验证
改用浏览器自身的显式 HTTP 代理和独立资料目录，不依赖浏览器 DLL 注入。WebRTC 限制写入本次新建资料目录的 Default/Preferences，并保留启动参数。没有修改普通 Edge 的资料或系统策略。

- **普通窗口集成 9/9**：真实 Edge GUI 打开含随机标记的自有测试页；实际调用 WebRTC API，读取真实 HTTPS IP 服务；IP 返回 `203.0.113.30`，WebRTC candidates 为 `[]`，自有 STUN 接收端 0 包。通过保留的自有控制 WebSocket 报告结果，无 UI 自动化或关闭证书校验。随后关闭自有测试代理监听及其既有公网连接，再发新的禁缓存 IP 请求，得到网络失败，没有取得本机回退 IP。见 `evidence/gui-final.json`。
- 测试浏览器自行关闭，Session 清理成功，apps=0。见 `evidence/gui-lifecycle.json`。
- **正对照**：仅有命令行 WebRTC 参数的旧测试产生 16 个直接 STUN 包和 UDP 候选，新版增加资料目录首选项后为 0。见 `evidence/webrtc-control.json`。
- **多程序 7/7**：两个真实测试 EXE 的 TCP/UDP 同时代理，未选程序不进入代理，活跃应用不会被强制结束，闲置会话清理。见 `evidence/multi-program.json`。
- **参数与范围策略**：所有项通过，涵盖冲突参数、临时资料首选项、端口 +1、无 DIRECT 配置、沙箱/证书检查未关闭、清理范围。见 `evidence/browser-policy.json`。
- 全局功能仍默认关闭且检测到 FlClash / 系统代理，本轮没有开启 TUN。见 `evidence/global-conflicts.json`。
- 关键进程、系统代理、路由与本次修改范围的前后检查，见 `evidence/preservation.json`。服务器操作为 none。

## 验收限制
真实浏览器测试为本机 Edge 156.0.4314.56，未逐一运行其他 Chromium 品牌或所有网站。IP 服务曾有超时；最终选择可访问且允许 CORS 的 myip.ipip.net 完成普通窗口验证。节点出口在独立探测中也曾见 `203.0.113.30`，不承诺宽带出口 IP 永久不变。公网网页的断代理失败测试不等同于系统级 UDP/防火墙拦截保证；localhost 仍保留浏览器默认旁路。手动全局 TUN 沿用旧版，未实际开启验收。
