# 3.0.1 浏览器后台实例拦截修复

## 原因
3.0 对所有同路径已有进程统一拒绝启动。Edge 即使关闭窗口，也可能留下后台主进程，导致连接器在启动新程序前就报错。用户的 TCP/UDP 出口测试通过，不会解除这个检查。

## 本轮验证
- 保留原有普通 Edge 后台主进程的同时，使用真实安装的 Edge 156.0.4314.56 启动独立资料目录的无头浏览器，经相同代理会话路径访问网页。
- 隔离 SOCKS5 测试：代理端收到带随机标记的 Edge HTTP 请求；未将请求发往真实的测试保留 IP。见 `evidence/browser-hook.json`。
- 实际节点重测：TCP、UDP 均通过，出口 `203.0.113.30`。见 `evidence/upstream-retest.json`。
- 实际 Edge HTTPS 网页显示出口 `203.0.113.30`，与节点检测相同。见 `evidence/edge-live-exit.png`、`evidence/browser-live.json`。网络探测初次有未产出截图的尝试，最终成功截图已人工核看；不宣称每个检测站都始终可达。
- 多程序回归 7/7：两程序 TCP/UDP 同时通过、独立会话、不强制结束活跃程序、未选程序不被代理、会话退出清理。见 `evidence/multi-program.json`。
- 浏览器参数/范围/清理策略 18/18：包括不同形式的资料目录及代理覆盖参数拒绝、普通参数通过、只清理本会话临时目录、范围外目录保留。见 `evidence/browser-policy.json`。
- 全局模式保持默认关闭，检测到原有 FlClash 与系统代理；本轮未启用 TUN。见 `evidence/global-conflicts.json`。
- 最终普通 Edge、FlClash、旧连接器进程和系统代理/路由保护检查，见 `evidence/preservation.json`。

## 适用范围
本次真实浏览器测试采用 Edge 无头模式，并非人工逐项验证 GUI、所有站点、WebRTC、QUIC 或具体游戏。Chrome / Brave / Chromium / Vivaldi 共用独立启动逻辑，未逐一实机运行；Opera / 360Chrome 维持旧版启动约束。

## 交付
保留 3.0 原包。3.0.1 通用包使用文件白名单，不含 `profile/runtime/sessions/private`、用户密码、连接卡私有缓存或测试程序。个人配置只在本机准备版中以原有 DPAPI 加密格式迁移，不进入 ZIP。
